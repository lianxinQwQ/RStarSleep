# AUR 增量构建改造计划

状态：Arch 0.12.0 已实现普通包复用、Git 源码检查、重建策略和依赖失效判断。
跨调用、拆分包、缓存修复、失败记录、配置传递及阶段缓存复用已有自动化验证；
本地 Git 与真实 makepkg 的离线构建/更新/复用已通过。真实 Btrfs+nspawn 完整链路
仍待特权集成环境验收，未声明的 ABI 关系仍需手动重建。

## 目标与默认行为

重复执行相同构建，未变化的 AUR 包直接复用已校验的二进制，不安装其临时构建依赖，
不调用源码验证和编译命令。多个系统及多次调用共享同一份有效产物。

借鉴 meowSub 的共享包池和 Paru 的开发包检查，但沿用本项目直接调用 makepkg 的
链路，不新增 Paru 依赖。默认检查 Git 上游更新；提供关闭开发源码检查和强制重建的策略。
关闭源码检查仍检查配方变化，不代表固定版本。

| 条件 | 处理 |
| --- | --- |
| 配方、架构、构建配置与源码状态一致，产物完整 | 复用 |
| 配方 Git commit 变化，包括未提高版本的配方修正 | 重建该 pkgbase |
| Git 源码所跟踪的引用变化，且开启开发源码检查 | 重建该 pkgbase |
| 缺少有效记录、文件缺失、摘要不符、架构或构建配置变化 | 重建该 pkgbase |
| 已有产物的 pkgver() 动态版本高于配方声明 | 不单独触发重建，按来源记录判断 |
| 用户指定强制重建 | 跳过复用判断，执行正常构建 |
| 更新查询失败 | 报告失败并保留旧事务状态，不把未知状态宣称为最新 |

这里优先采用配方身份而非单纯版本比较：本项目已经获取最新配方，可以发现同版本的
打包修正；也不会因为动态 pkgver 与声明版本不同而无限重建。拉取配方仍有网络开销，
但远低于编译。不默认提供断网时静默使用旧包的行为。

## 现有实现与修改位置

- `presets/plugins/arch/lib/predownload.py`：`load_base()` 已获取最新配方 commit；
  `build()` 在同次调用去重之外加入持久复用判断。
- `ensure()` 同时服务目标与构建依赖，必须让两类调用共享复用逻辑。
- `publish()` 使用 `.packages.json` 维护仓库归属；保留其职责。
- `finish()` 的 `.prepared.json` 是本次准备结果，会被覆盖，不能充当全量历史索引。
- `prepare_systems()` 构建后按实际二进制运行依赖复核计划；复用路径也必须执行此逻辑。
- `tests/arch_predownload.py`、`tests/arch_aur_cache.py`：验证跨调用复用、依赖闭包、
  失败记录及真实 Git/makepkg 行为。
- 配置贯穿 `presets/plugins/arch/plugin.toml`、插件脚本/配置读取和核心预下载参数适配。
  预下载仍接收部分旧环境变量，不能只在 Python 中新增变量而漏掉传递链路。

## 持久记录与事务

在 `state/repository` 增加带格式版本的 `.aur-builds.json`，按架构和 pkgbase 索引。
每条记录至少包含：

- 配方 commit、架构、构建配置指纹、缓存格式版本。
- 全部拆分包的包名、实际版本、文件名、SHA-256、运行依赖、provides、conflicts。
- 源码标识及实际构建所用 Git revision；AUR 构建依赖的产物身份，用于传递失效。

记录保持所有有效 pkgbase，不随本次请求包集合覆盖；清理时才移除过期记录及产物。
仓库归属、构建索引、本次准备清单分开管理，避免把“未在本次请求中出现”视为失效。

读取时校验格式、字段、路径、架构和文件类型。命中记录后校验产物摘要与包元数据，
确保仓库和下载缓存所需文件存在；仅缺少一份副本时可从另一份已验证文件恢复。
拆分包以 pkgbase 为单位记录和失效，不允许混用同一组的新旧构建产物。

索引与产物发布沿用现有持久卷 CoW 事务；只有构建、产物检查、仓库发布均成功才
提交记录。复用成功也将产物加入本次 `self.artifacts`，进入最终校验和准备清单。
任何失败不得破坏之前可用的包、索引和仓库数据库。

旧缓存缺少来源或配置指纹时，不臆测其有效性：首次按需重建一次并建立记录；
现有 `.prepared.json`、`.packages.json` 保持可读，不要求用户手动清空缓存。

## 复用路径

`build(base)` 在准备构建依赖之前判断能否复用：

1. 进入现有循环依赖状态管理，读取该 pkgbase 的持久记录。
2. 比较配方、架构、配置和适用的源码状态，校验全套产物。
3. 命中时恢复实际二进制元数据，更新 `base` 的运行依赖、provides、conflicts 与版本。
4. 将产物登记到本次结果，确保本地仓库可用，解析并准备实际运行依赖。
5. 标记完成；只在未命中时准备构建依赖、校验源码并运行 makepkg。

新构建与复用共用“应用二进制元数据并准备运行依赖”代码，避免两条路径的计划不同。
复用时不拉入 makedepends/checkdepends；运行依赖变化仍通过当前仓库解析处理。

配置指纹包含影响输出的 makepkg 配置及插件构建语义版本，排除临时路径、镜像地址、
本次目标列表等无关变化。不要把整个插件版本或所有已安装包版本直接作为失效条件，
否则常规更新会再次退化成全部重编。明确指纹的规范化规则并纳入测试。

## Git 开发源码策略

按解析后的 source 项识别 Git 源码，不只靠包名的 `-git` 后缀。
支持默认 HEAD、branch、tag 与固定 commit，并处理别名及多个 Git 源。

- HEAD/branch：比较远端解析后的提交。
- tag：正确处理 annotated tag 的 peeled commit；引用移动也视为变化。
- 固定 commit：不因远端其他提交变化而重建。
- 多个源码：任一适用源码变化即失效。

记录实际进入构建的 revision，不能把构建前查询结果直接当作实际构建来源。
实现采用下载/验证后读取 makepkg 本地 mirror 中选定的提交，再以 `--holdver` 构建
该快照；下载后复核远端，不能确认下载内容已更新时中止。mirror 由现有持久事务
独占锁保护；不在 prepare() 之后读取 HEAD，避免配方新增提交造成永久缓存未命中。

无法可靠识别的动态或其他 VCS 源码先保守构建并说明原因，不能静默宣称已检查更新。
Git 检查完成后已开放可识别 Git 源的默认复用。
明确固定的发布归档按配方身份复用；可变 HTTP 资源或 SKIP 校验等来源列入保守策略，
并说明按配方复用无法发现维护者未改配方的远端内容替换。

## 配置与用户反馈

已增加 Arch 发行版配置：

- `AurDevel = true`：默认检查 Git 开发源码引用；false 仅按配方与缓存状态判断。
- `AurRebuild = none`：支持 `none`、`all`、指定 pkgbase 列表；用于明确要求重编或
  修复 ABI 问题。当前是持久配置，会持续强制重建，用后恢复 `none`。

策略仅决定软件准备，不能因改变一个重建选项就清空基础系统或所有阶段缓存。
兼容单系统、多系统、构建依赖和 provider 解析；预下载关闭时保持不编译行为。

日志明确区分“复用 N 个 pkgbase”“重建 N 个 pkgbase”，逐项给出重建原因。
Git 检查关闭时说明没有检查开发源码；查询失败不能输出“全部最新”。

## 分阶段实施与验收

### P1：先消除普通包的重复编译

实现与自动化验收已完成。

实现持久索引、普通包复用、拆分包一致性、共享二进制元数据处理和强制重建入口。
可变源码先保守构建。更新 Arch 使用文档与构建设计说明。

验收：同一请求连续执行两次，第二次普通 AUR 包不运行源码验证/编译，也不准备其
临时构建依赖；本次计划和清单仍完整。跨系统复用、目标移出再加入仍命中。
配方变更、产物损坏、配置变化均触发重建；失败后旧事务结果保持有效。

### P2：消除未变化 Git 包的重复编译

实现与自动化验收已完成，包含真实 makepkg 中 prepare() 新增提交的回归验证。

实现源码识别、revision 记录与远端检查，打通 `AurDevel` 配置传递。
测试 HEAD、branch、annotated tag、固定 commit、多 source 与检查失败。

验收：上游不变不编译；新增跟踪提交只重建受影响 pkgbase；AUR 声明版本不变也能
发现上游更新；动态 pkgver 不导致下轮重复编译；关闭检查时策略符合文档。

### P3：完善依赖失效与真实环境验证

AUR 构建依赖产物变化的递归失效、显式版本化 SONAME 无法满足时的重建已实现，
普通官方依赖的小版本变化不一律失效。真实 Btrfs+nspawn 完整事务验证仍待执行。

定义 AUR 构建依赖产物变化后的传递失效，并检测已能可靠识别的共享库依赖变化。
不将全部依赖版本变化直接等同于 ABI 变化；无法自动判定的情况提供明确强制重建方式。
P1/P2 不承诺自动解决所有 ABI 变化，文档必须说明这一限制。

以隔离 nspawn/Btrfs 环境验证普通包、Git 包、拆分包和 AUR 构建依赖，覆盖完整事务
成功与失败恢复；模拟工具测试通过不能替代该验收。先运行现有 Arch 相关测试，
涉及核心参数传递时补跑相关 Rust 检查，避免无关扩展测试。

最终完成标准：相同输入连续构建时无需重编，真实更新能触发对应重建，产物和运行
依赖完整，失败不覆盖旧有效结果，并能通过日志解释每次重建原因。
