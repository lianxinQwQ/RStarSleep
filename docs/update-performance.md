# 日常更新性能

## 软件数据库变更监听

插件可声明 `package_database_paths = ["var/lib/pacman/local"]`，各路径是目标根内的相对数据库目录。控制器在创建脚本工作根后、构建期继承之前用 inotify 递归监听，覆盖插件后处理和用户脚本；数据库未变化时复用软件阶段的包清单和安装原因，保持后处理接口可以修改软件的语义。

缺失、链接、外部硬链接、注册失败、目录替换、监听失效和事件队列溢出均保守回退到完整查询。监听不跨构建保存；未声明能力的旧插件保持原有查询行为。该能力针对正常包管理器写入与文件系统操作，不作为限制特权脚本的安全沙箱。文件所属清单仍单独生成。

目录和已有普通数据库文件均注册监听，后续新建树外硬链接及经其写入也会使复用失效。Linux inotify 不报告 mmap 写入，具有此类数据库写入方式的插件应省略此能力并保持完整查询。

可选 `query_package_database_paths = true` 操作优先于静态目录声明，每行返回一个目标根相对目录。Arch 使用同一临时 pacman 配置及 `pacman-conf DBPath` 解析实际目录，兼容自定义 DBPath、RootDir 和 Include；软件清单完成后将路径与清单一起保存，脚本阶段监听此路径，完成后再次解析，路径一致且监听无事件才复用。旧缓存缺少路径依据时完整查询，避免跨构建修改 DBPath 后沿用旧清单。路径解析单独计时，失败、空结果或无效路径均保守查询。

## 同次预下载摘要复用

官方包验签缓存、AUR 元数据检查和最终清单共用本次调用的摘要结果。缓存键包含设备、inode、大小以及纳秒 mtime/ctime；文件改写或替换会重新计算，读取期间变化则失败。摘要缓存不跨调用持久化，签名信任上下文及有效期检查继续生效。

## 未变化 AUR 仓库条目

完整发布后记录仓库数据库摘要和所属产物清单；同一 pkgbase 的全部产物及已发布条目相同、数据库与发布记录匹配时跳过 repo-add。旧缓存、记录缺失或数据库变化会重新发布一次。构建产物及运行依赖检查保持原有行为。

## 本地查询只读持久数据

新增可选 `readonly_queries` 声明，仅允许 query_packages、list_orphans、query_package_files、query_package_database_paths。此类调用持有全局持久锁并先恢复中断事务，随后直接只读绑定已发布卷，不创建、提交 CoW 工作卷；缺失卷使用本次调用的临时空目录。旧插件和需要写缓存的 collect_packages/resolve_packages 仍使用事务。

Arch 的 -Q 类命令不再修复共享缓存权限、复制同步数据库或补齐持久配置，只生成临时配置后读取目标本地数据库。

## 缓存准备复用

旧公开缓存的权限迁移按目录代次执行；目录条目未变化时只比较代次，不扫描全部包；新生成的 AUR 仓库数据库显式设置公开可读权限。准备好的仓库数据库复制时保留时间戳，后续调用以时间戳和大小识别同代副本，避免重复写入。默认配置文件完整时跳过 cp 和 chmod，缺文件仍补齐。

## 密钥环准备复用

每个目标密钥目录保存准备凭据，覆盖配置、已安装与仓库中的 keyring 元数据、GPG 公钥/信任状态和发行版密钥环文件。有效期/撤销状态由每次 GPG 查询参与指纹；输入未变时跳过重复签名和 populate。refresh 模式仍同步仓库并检查 keyring 更新，信任或软件包改变后重新准备。

## 仓库限定目标的重复安装

首次应用 repo/package 仍强制安装，保持同版本切换来源。成功后保存目标来源、仓库元数据、已安装版本和本地 desc 的内容/时间戳凭据；下次全部匹配时不再单独重装。来源、版本、描述或本地重装发生变化则失效。缺少标准本地数据库描述文件时保持保守重装。

## 独立计时与空载判定

日志新增解析环境初始化、AUR 缓存检查、本地仓库发布、最终清单、实际摘要读取字节/时间、AUR 元数据下载/索引及软件包文件清单生成的计时。原有构建环境维护和 initramfs 计时保留。

性能比较应在相同配置/插件/缓存条件下分别记录实际更新和空载构建。空载需确认构建环境及目标 pacman 均无更新、没有新增官方包验签、AUR 重建为零；报告阶段实测，不能把一轮含下载/更新的全部准备时间视为可省开销。此次不改变这些有功能产出的操作，只提供独立计时以便决定后续是否按需生成。

本地查询在持久配置尚未初始化时直接读取包内默认模板，不为了查询写入 data；缓存目录新增文件后会触发一次权限检查，兼容旧写入方。
